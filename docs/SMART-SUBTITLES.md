# 智能字幕

2026-10-12。功能参考 [subtitle.im 的 V2EX 介绍](https://www.v2ex.com/t/1246427)，在 BiliNext 的原生 mpv 播放器中独立实现。

## 使用

播放器下方的「字幕与弹幕设置」中可开启自动检测与自动开启可用软字幕。画面硬字幕和软字幕语言不同，可选择保留、先询问或隐藏；询问直接显示在播放器中。

可为此 UP 主或当前视频分 P 设置始终保留／始终隐藏。视频规则优先于 UP 主规则，视频规则按字幕语言分别保存到本机偏好。「记住此视频的隐藏结果」保存显式确认的关闭结果。

播放器字幕按钮和「恢复软字幕」都是本次观看的手动选择，后续检测不会覆盖它；跳转也保留手动选择。「重新检测」、更改规则或切换字幕语言会重新开始自动判断。Transcript 始终保留完整脚本，不因画面软字幕隐藏而删除或停止加载。

## 检测

- 仅在当前标签播放且不缓冲时检测，每 4 秒最多取样一次；同一条字幕不会反复累计。
- 从已有 mpv 渲染器生成至多 1280×720 的离屏视频帧，兼容 VideoToolbox 零拷贝硬件解码，不含 SwiftUI 字幕、弹幕和播放器按钮。
- Apple Vision 在后台识别画面下方 40% 区域的文字，使用中文、英文、日文和韩文识别语言。取样不保存到磁盘，不上传服务器，也不需要屏幕录制权限。
- 对齐字幕时间后比较文字，忽略标点、大小写和少量 OCR 错误。至少三条不同软字幕与画面文字匹配后才自动隐藏。
- 语言不同必须取得三个不同软字幕和三个不同画面文字的高置信语言证据。短文字、重复静态招牌、取样失败或证据不足时保留软字幕。
- 切视频、分 P、字幕语言、跳转和手动恢复会取消旧检测结果，防止迟到的 OCR 改变当前观看状态。

## 边界

本机官方客户端核心仍使用自己的字幕控制，不接入此检测。画面上方字幕、竖排字、很小或复杂的字幕、语言模型低置信度等可能无法识别；没有可用软字幕的视频不会开始检测。自动关闭后本次播放保持隐藏，跳转或重新检测会重新评估；不会自动保存未经用户确认的关闭结论。

## 验证

默认离线测试覆盖文字容错、不同字幕证据计数、跳转、静态招牌防误判、语言识别、规则优先级、持久化及手动覆盖；同时使用合成中英文图片调用真实 Vision OCR。

`BILINEXT_SUBTITLE_TEST=1 swift test --filter 'Subtitle|OCR|rawMPVFrames'` 额外生成三段硬字幕视频，用真实 libmpv + VideoToolbox + OpenGL 渲染读取画面，验证自动隐藏、恢复、语言不同询问和手动选择。需本机 `/opt/homebrew/bin/ffmpeg`；不联网，不访问用户账号，结束后删除临时视频。

本轮签名 Debug App 实际界面已验证设置布局、手动隐藏后状态和记住结果入口、播放器字幕按钮恢复、无可用 Transcript 空状态；合成视频覆盖完整自动检测链路。Release 构建与签名检查通过，启动一度等待钥匙串授权；用户报告每次启动仍重复授权并要求后续修复，此问题不在本轮字幕实现中修改。
