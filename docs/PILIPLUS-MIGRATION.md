# PiliPlus 功能迁移清单

用户于 2026-10-04 授权以 PiliPlus 全部功能为参考继续开发。该目标范围大于原先首版规划；按真实实现和验证逐项推进，不能把下表的源码定位等同于功能完成。

播放器采用自定义控制界面和弹幕覆盖层；底层媒体引擎独立选择。账号写操作只由用户明确点击触发，开发验收默认只读。

## 当前执行顺序

1. 自定义播放器、弹幕分段加载与时间同步、清晰度和分轨可行性。
2. 评论与回复详情、相关推荐、UP 主视频页。
3. 首页推荐／热门／排行榜、搜索排序与分页、资料库交互。
4. 动态详情、番剧、直播、下载及剩余模块按依赖推进。

## 本轮证据和边界

- Debug 构建及 8 个纯单元测试、3 个账号只读集成测试通过；公开接口测试默认跳过。
- 真实播放验收：BV1GJ411x7h7，画面、进度推进、暂停、字幕和弹幕；弹幕分段返回 10,661 条，渲染按防追尾轨道调度，不保证每条都上屏。
- 初始短视频预取不存在分段的问题已修正：未知时长只取当前段，邻段预取错误不掩盖当前段成功。
- UI 已打开评论、相关推荐、UP 主投稿、收藏选择；未替用户点赞、投币或保存收藏。
- 本地下载完成并用 ffprobe 验证视频／音频轨和完整时长；下载文件保留在用户 Downloads/BiliNext。
- 番剧正片接口、全部动态及下一页、收藏／历史搜索已做只读联调；不代表所有番剧权限或所有动态类型已覆盖。
- 高级功能仍以表中的待办为准，不能把一个入口或部分页面记作整个 PiliPlus 模块完成。

### 未登录风控（2026-10-14 记录，待定）

- UP 主投稿按「最多播放」排序与投稿搜索只能走签名接口 `/x/space/wbi/arc/search`。未登录时 B 站返回 -352／412；登录后（开发会话只读实测）正常。
- 参考项目的做法：bilibili-api 与 PiliPlus 都给签名请求附带伪造的 `dm_img_*` 浏览器指纹；PiliPlus 还改走 Android App 接口并用 App 密钥签名。两者都会激活 gaia（`ExClimbWuzhi`，载荷同样是伪造指纹）。
- 不伪造时的尝试：buvid3／buvid4、bili_ticket（`GenWebTicket`，真实网页握手）均无法让未登录请求通过。
- 当前取舍：不发送伪造指纹、不冒充 App。未登录时不发请求，页面提示登录（扫码登录或回到「最新发布」）；「最新发布」用无需签名的 `/x/space/arc/list`。若以后要支持未登录排序／搜索，需要先就「是否接受伪造指纹」做决定。

- 用户指出此前鬼灭样本涉及地区权限，因此改用国创《凡人修仙传》第一集 BV1vT411d7QE；没有把受限片源算作播放器成功或失败的通用基准。
- 国内样本已实际显示正片和弹幕，时长 20:03；720P → 360P 保留位置，跳到 10:00 后继续播放及对应弹幕通过。
- 媒体改用 AVFoundation 公共 ResourceLoader 接口，通过 URLSession 发送正常 Referer/User-Agent 与 Range 请求；没有使用私有 HTTPHeaderFieldsKey，也不绕过官方地区／付费权限。
- 清晰度和倍速改成自定义弹出面板，避免播放控件依赖系统菜单；暂停状态的时长通过 KVO 及时更新。
- 新增全部动态、首页推荐、影视分类、正片列表的 UI 验收；标签行补充了独立可访问性按钮。

## 2026-10-05 播放性能修复

- 移除 30 Hz SwiftUI Canvas 全量扫描、逐帧文字排版和阴影绘制。使用 NSView 屏幕刷新回调及缓存 CATextLayer，只检索当前时间窗口的可见弹幕；布局和 CoreText 测宽放到后台任务。
- 运行时采样发现 Transcript 每一行都重复计算整份字幕的活动项和搜索匹配；改为每次视图更新计算一次并共享集合。
- 视频标题栏增加 H5 按钮：独立 WKWebView 窗口加载官方外链播放器，使用内存 Cookie 存储，打开时暂停原播放器并传入当前时间。真实视频页面、画面、播放控件已验证。外链播放器有官方清晰度限制；H5 窗口的进度与原生 Transcript、会话保存暂未双向同步。
- 没有进行官方客户端逆向。截图与短时采样不等同于完整帧时间基准；持续流畅度仍需长时间、高密度弹幕验收。

## 2026-10-05 官网 H5 与客户端检查

H5 已改为当前播放区域内的官网视频页，增加原播放器切换、媒体时间/暂停状态回传、Transcript 跳转与会话进度保存；旧独立窗口实现已移除。官网 DOM 样式和 WebKit 播放兼容性仍需持续验收。客户端只读分析记录见 `OFFICIAL-CLIENT-PLAYER.md`；已定位 nano 核心和 PC_APP 宿主接口，尚未移植该核心。
