## 渲染死锁修复与系统「正在播放」（2026-10-14）

- 用户反馈点击评论区后整窗卡死、视频仍在播。系统 CPU 报告与代码排查指向渲染线程的锁顺序：渲染队列在持有绘制锁时 `CATransaction.flush` 要等 Core Animation 事务锁，而主线程在提交布局时让视频层重画、去等绘制锁；关闭标签时主线程还会同步等待渲染队列。修复后所有绘制只在渲染队列进行，主线程的重画请求转交队列，释放渲染器改为异步并持有播放器直到完成。未能复现原始卡死（向进程投递的点击未送达），根因为推断。评论的「赞」只是标签，点击本身无动作。
- 新增 `NowPlaying`：选中标签的标题、UP 主、分 P、封面、时长与进度发布到 `MPNowPlayingInfoCenter`，每秒采样、无变化不重发；`MPRemoteCommandCenter` 的播放／暂停／切换、前后 10 秒、拖动进度、上一个／下一个（分 P）路由到选中标签，直播只开放播放暂停。命令回调不等待主线程。
- 新增离线检查：渲染队列被占用时主线程的重画请求和释放立即返回；「正在播放」条目内容。默认 `swift test` 156 项、Release 构建与严格格式检查通过；`BILINEXT_MPV_TEST=1` 的标签切换、DASH 与新增的 `pausedVideoRedrawsAcrossResizes`（真实窗口暂停后两次缩放画面不黑），`BILINEXT_SUBTITLE_TEST=1` 取帧测试通过。测试包中连续切换剧场模式 16 次后界面仍响应（未播放，避免上报观看历史）。
- 未验证：控制中心与菜单栏实际显示、媒体键与耳机按键、封面图、长时间播放中的卡死是否再现。

## 播放流畅度：视频渲染移出主线程（2026-10-14）

- 用户反馈播放卡顿。对播放中的 Debug 进程 `sample` 3 秒：主线程约 1/4 时间阻塞在 SwiftUI `RBLayer display` 等待渲染服务同步，来源是侧栏标签与简介当前项上持续循环的音波 `symbolEffect`；而视频帧由 `NSOpenGLView` 在主线程绘制，主线程一忙即掉帧。mpv 内核与选项未改。
- 修复：音波改为静止图标；视频改由 `MPVVideoLayer`（`CAOpenGLLayer`）在独立渲染队列绘制，字幕识别取帧同步迁移。另修复全局提示在播放页不消失（计时从视图 `.task` 移入模型，新增离线测试），播放时提示抬到控制条上方。
- 默认 `swift test` 153 项、Release 构建与严格格式检查通过；`BILINEXT_MPV_TEST=1` 的 `playbackTabSwitchRetainsLoadedMedia`、`mpvDirectDASHPlaysSeeksSwitchesAndRetainsTabs` 与 `BILINEXT_SUBTITLE_TEST=1` 的 `rawMPVFramesDriveAutomaticSubtitleHidingAndRecovery` 通过。测试中发现并修复渲染上下文晚于 mpv 核心释放导致的 abort。
- 未验证：真实窗口中改动后的播放流畅度与采样对比、窗口缩放与全屏切换时的画面、Retina 清晰度、小窗与直播画面、多标签切换时的黑帧。
